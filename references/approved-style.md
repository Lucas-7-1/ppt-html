# 默认视觉基准：同一种审美，两种载体

这是用户明确要求延续的已认可方向。没有新的品牌或视觉指令时，直接以此为起点，不重新随机选风格。先实际打开 [成对参考预览](../assets/approved-style/reference.png)，再查看 [参考项目](../assets/approved-style/reference/deck.json) 中最相关的 SVG / HTML 页面。文字说明不能代替看作品。

## 固定什么

- **鲜明的主次**：一个主导视觉关系，辅助证据紧邻它。主视觉可以是结构、工作对象或有口径的数据，不默认放大页码、标题或数字。
- **编辑式排版**：清楚的字号落差、少量对齐轴、有语义的中文断行、紧密的证据分组。留白围绕主体组织。
- **具体对象与空间**：用一张决策书、一条连续时间轴、一则沟通消息等承载相应内容。纸张的偏移阴影、局部裁切和轻微错位可以保留；不将信息一律摊平为并列列表。
- **有职责的色彩**：冷灰纸面承载阅读，蓝色建立重点，荧光浅绿用于决策和强调，深墨色建立停顿。背景切换由叙事决定。
- **整套节奏**：开场、证据、解释、决定拥有不同视觉重量；复杂内页也必须成立。用页序和密度推进理解，不追求最少页数。

这些关系在 PPT 和 HTML 中都要成立。载体不会自动带来美感。

## 共用参数

[tokens.json](../assets/approved-style/tokens.json) 是默认颜色、字体、比例的唯一参数来源。HTML 构建器直接读取；SVG 作者按同一参数创建原生文字和形状。

| 要素 | 默认起点 | 用途 |
| --- | --- | --- |
| 蓝 / 浅绿 | `#3455F5` / `#DDF584` | 重点、强调与画面识别 |
| 墨 / 纸 / 白 | `#111824` / `#F4F6F9` / `#FFFFFF` | 正文、阅读背景、工作对象 |
| 字体 | Noto Sans SC，400 / 700 | 中英文和数字保持一致，必须实际可用 |
| 画布 | PPT 1280×720；HTML 1440×810 | 同为 16:9，尺度相差 8/9 |
| 横边距 | HTML 76 px；PPT 约 68 px | 页面之间共用对齐轴 |
| 字号 | HTML 主视觉 76–92、标题 62、正文 24 px | PPT 按比例换算；按语义和行长微调 |

以上是已验证的起点，不是强制将每页变成同一字号或同一布局。保持层级和比例，比机械锁死每一个坐标更重要。新字体、色彩或尺寸只有在用户要求或材料确实需要时调整，并记录为什么。

## 哪些内容该怎样画

| 内容关系 | 可用构图 | 迁移时保留 |
| --- | --- | --- |
| 进入新阶段、主题开场 | 排版与有意义的概念空间 | 主体完整、尺度差、裁切关系；拱门只适用于合适的概念 |
| 阶段、交叠、进度 | 同一尺度的连续时间轴 | 起止、交叠、里程碑与标签关系，不能换成三个等宽数字 |
| 工作约定、决策、证据 | 一份真实结构的文档 | 建议、依据、条件、请求的邻近与主次 |
| 沟通、反馈、行动请求 | 一则消息或批注 | 主体语句与具体请求；不要整页堆聊天气泡 |
| 定量结果 | 同尺度图表、结果与证据组合 | 数据与单位、比较基准；不能为了极简删掉关键口径 |
| 收束、需要的决定 | 关键请求加少量行动 | 让用户知道接下来做什么；并非每套必须有结束页 |

参考页是可编辑的构图示范，不是“所有任务套六页”。使用新内容决定需要哪些页面、图表与密度。不要复制参考页里的虚构事实、页序、天数和措辞。

## 两种载体的等效表达

- PPT：真实文本框、矢量曲线、按语义分组的形状；用偏移色块表达纸张厚度，用原生几何表达关系。SVG 不支持的 CSS 效果不能直接混入源稿。转换限制不能成为删掉主体或压平结构的理由。
- HTML：真实 DOM 文字、CSS 排版、内联 SVG 图形；沿用同样的视觉角色。导航放在画布外。桌面为演示画面，手机为可读的重排，不强行缩成一张小图。
- 同时交付：复用同一份事实、页面 ID、结论、备注与视觉决策，分别生成两份原生源稿；并排检查相应代表页。无需逐像素一致，但不能出现一份精致、一份只剩提纲的落差。

## 防止再次退步

必须并排看新稿与本基准中的相应页面，至少覆盖主视觉页、最复杂内页及整套缩略图。修改已认可作品时，还要直接比较修改前后的同页。

若出现以下变化，先解释内容上的必要性，再决定是否保留：主体变成无意义的巨型数字；时间关系变成等宽栏；具体文档变成普通条目；亮点被中性配色削弱；为减少页数挤掉讲述节奏。不要让“更统一、更极简”自动覆盖已成立的表达。

依次检查主次、构图、节奏、细节。技术检查通过后仍要看真实渲染；不得自评分证明美感。已有方向的调整没有明显改善，就保留原方案。
